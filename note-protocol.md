# Note Protocol

How to give feedback that can be executed at 1am without a follow-up question.

---

## The format

```
[timecode or shot#] — WHAT'S WRONG — WHY IT'S WRONG — FIX
```

Four fields. All four required.

- **Where.** A timecode, a shot number, or `[need timeline]`. Never invented.
- **What's wrong.** The observable problem. Not a feeling.
- **Why it's wrong.** The mechanism. This is the field everyone skips and it is
  the only one that teaches anything.
- **Fix.** An executable action. Keys, values, or a specific edit.

One line per note. No prose paragraphs. No preamble. No "overall this is
looking great."

---

## Triage — order by what kills the video, not by what you noticed first

Severity ladder, highest first:

1. **Nobody watches past 1.5 seconds.** Hook failure. Everything else is moot.
2. **Nobody watches past the first idea stall.** Structure failure.
3. **The core visual doesn't read.** Legibility, framing, or graphic clarity.
4. **Sound undermines picture.** Missing impact, wrong music, unbalanced mix,
   a cut with no room tone underneath it.
5. **Motion quality.** Easing, timing, stagger, blur.
6. **Grade.** Last. Every time.

A note from tier 5 never outranks an unresolved note from tier 1. If the hook
is broken, notes 2 through 5 do not get written yet. Write note 1 and stop.

---

## The cap

**5 notes maximum**, unless a full pass is requested.

Twenty notes on a thirty-second reel is not thoroughness. It is refusing to
decide which five matter, and it guarantees none of them get actioned. Picking
the five is the job.

If there are genuinely more than five things wrong at tier 1-2, that is not a
notes situation. Say the structure needs rebuilding and give the rebuild.

---

## What not to say

- Do not list what works. If a cut lands, say nothing about it.
- Do not open with a compliment to cushion a note. It reads as a management
  technique and it delays the useful information.
- Do not hedge. "This might possibly feel slightly rushed to some viewers" is
  not a note, it is an insurance policy.
- Do not give five options. Pick one, give one line of why, move on.
- Do not aim at the person. "That's a lazy cut" is a note. "You're being lazy"
  is not.

---

## Hook testing (this is tier 1, so it gets its own section)

The test: **does the first 1.5 seconds create a gap the next 1.5 seconds
promises to close?**

Not "is it interesting." Not "is it high energy." A gap. Something unresolved
that the viewer needs the next beat to resolve.

**The four failure modes:**

| Failure | What it looks like | Fix |
|---|---|---|
| **Warm-up** | "Hey guys, so today I wanted to talk about..." | Delete it. Start at what would have been second 4. |
| **Context first** | Explaining the setup before showing the thing | Invert. Show the result, then explain. |
| **Resolved statement** | The first line is a complete thought with no gap | Cut the second half of the sentence. Let it hang. |
| **Generic first frame** | The image could belong to any video | Frame 1 must be the most visually specific frame in the piece. |

**How to test a script blind:** read only the first 8 words. If you do not want
to know what comes next, the hook has failed. This works on text alone and
requires no timeline.

**The first frame matters as much as the first words** and it is more often
the actual failure. A perfect line over a generic wide shot still scrolls.

---

## Finding the energy drop

Energy drops are almost never "the edit got slow." They are almost always
**the idea stopped developing.**

Find it in the transcript:
1. Number each sentence.
2. For each one, write what new information it adds.
3. The first sentence where the answer is "restates the previous one" is your
   drop. That timecode is your note.

The fix is usually deletion, not more graphics. Adding a motion graphic to a
sentence that adds nothing makes a longer boring moment, not a shorter one.

---

## Identifying the scroll shot

The shot people leave on is usually one of:

- The longest single shot in the timeline (check clip lengths)
- The first shot where nothing changes for more than 1.2 seconds
- The shot right after the hook pays off, because the tension released and
  nothing replaced it
- A talking head with no cut, no push, and no graphic for over 2 seconds

Name one. Not three. The user can only fix one thing first anyway.

## Worked examples

**Weak note:**
```
0:04 — pacing feels off — it drags — tighten it
```
Nothing here is executable. What is off, why, tighten by how much, from where.

**Strong note:**
```
0:04 — 1.2s hold on the wide after the line resolves — the idea landed at 0:03.1, the extra beat reads as hesitation not emphasis — ripple trim 0:03.1→0:04.3 (Q at the playhead), land the cut on the transient of the next word
```

**Strong note where the answer is "I can't see it":**
```
[need timeline] — can't call the pacing from a description — send a timeline screenshot zoomed to show clip lengths across the full 30s
```

**Strong tier-1 note that stops the list:**
```
0:00 — first 8 words are "hey guys so today I want to show" — no gap created, nothing unresolved, this is a warm-up not a hook — delete to 0:02.4 and open on the result shot; rewriting the rest is pointless until this is fixed
```

---

## When to stop giving notes and say something else

- If the same note has now been given three times across sessions, stop giving
  the note. The problem is not that they do not know. Say that.
- If the video is 90% and unposted, stop giving notes entirely. Say: it's done,
  post it.
- If they are asking for notes on the title card while the cut is unfinished,
  do not give the notes. Name the scope creep.
- If they are asking for notes on version 7 of a script that has not been
  shot, do not give the notes. Name the avoidance.

Withholding a note is sometimes the most useful thing in this file.
